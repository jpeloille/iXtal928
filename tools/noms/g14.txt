// noms: G14 — les puces prennent leur nom (PLAN-G14.md, décisions n° 1 à 4). Ancien → nouveau → ce qu'il désigne.
//   La forme est celle des blocs `// noms:` de Floppy/ et Disc/ (fdc.cs:10-49), lue par les outils de la preuve :
//   tools/listings-jit.sh compare --noms, tools/ildump (l'IL) et tools/renommage (le renommage). Une seule table.
//
// La grammaire, que les trois outils appliquent à l'identique :
//   - une ligne « // étape X » ouvre l'étape X ; --jusqua X prend les étapes du début jusqu'à X comprise, dans l'ordre
//     du fichier (la référence est le commit R, d'avant tout renommage : les étapes se cumulent) ;
//   - une entrée est une ligne « //   ANCIEN  NOUVEAU  [ce qu'il désigne] », trois espaces après « // » : ANCIEN et
//     NOUVEAU sont deux mots, tous deux un nom de type qualifié (iXtal26.…) ou tous deux un chemin du dépôt
//     (iXtal26/….cs) ; le reste de la ligne est un commentaire ;
//   - toute autre ligne est de la prose. Une ligne qui commence par « //   iXtal26 » et n'est pas une entrée valide
//     fait refuser la table, comme un ANCIEN en double, un NOUVEAU en double, ANCIEN = NOUVEAU, ou une chaîne (un
//     NOUVEAU qui est l'ANCIEN d'une autre entrée).
//
// Ce que la table contient, et pourquoi :
//   - les types de PREMIER NIVEAU seulement. Les types imbriqués (pic.Etat8259…) suivent leur conteneur : un outil
//     les déduit du nom du conteneur, jamais d'une entrée ;
//   - le conteneur renommé (décision n° 1 : la classe, son fichier, son répertoire, son espace de noms) ;
//   - les autres types déclarés dans le même fichier (les types d'état, les délégués), qui GARDENT leur nom (décision
//     n° 1) mais suivent l'espace de noms du fichier, iXtal26.Ics (décision n° 2 : le répertoire et l'espace de noms
//     coïncident ; un fichier C# n'a qu'un espace de noms de fichier). Une entrée manquante pour l'un d'eux fait
//     refuser le renommage (tools/renommage : un fichier dont une partie des types seulement change d'espace) ;
//   - les fichiers déplacés par `git mv`, .Materiel.cs compris. Aucun espace de noms n'est renommé en entier :
//     iXtal26.Models, .Keyboard, .Devices, .Sound et .Video restent, seuls les types listés en sortent.
//   Les membres (fonctions, champs, constantes) ne sont jamais dans la table : ils gardent les noms de PCem
//   (décision n° 1, fdc.cs:47). Une entrée qui désigne un membre est refusée.
//
